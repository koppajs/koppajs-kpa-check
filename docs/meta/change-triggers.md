# Change Triggers

- Behavior changes: update the governing spec in `docs/specs/`, relevant tests,
  and `README.md` when the public contract changed.
- Architecture or module-boundary changes: update `ARCHITECTURE.md` and
  `docs/architecture/*`.
- Durable technical choices: add or update an ADR in `docs/adr/*`.
- Quality-gate or tooling changes: update `TESTING_STRATEGY.md` and
  `docs/quality/*`.
- Release model or publish-surface changes: update `RELEASE.md`,
  `CHANGELOG.md`, `README.md`, and the relevant package metadata tests.
- Contributor workflow changes: update `CONTRIBUTING.md`.
